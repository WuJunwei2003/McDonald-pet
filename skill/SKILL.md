# 麦麦精灵 McPet 🍟

一个基于麦当劳官方 MCP 的养成系 Skill：领养一只麦麦精灵，它吃你**真实的麦当劳订单**长大——喂薯条多长成薯系、喂牛肉堡多长成牛系，喂得越杂越可能触发稀有的**变异体**。

## 前置条件

- Python 3.10+（运行时零第三方依赖）
- 同步**真实订单**需要麦当劳 MCP Token（可选；没有 Token 也能用模拟订单完整体验）

## 第一步：定位项目根目录（每次会话必做）

本技能随「麦麦精灵」仓库分发，命令入口是仓库根目录的 `mcpet.py`。执行任何命令前，先按优先级确认项目根目录：

1. 环境变量 `MCPET_HOME`（若已设置，直接用）
2. 若本技能安装于 `~/.workbuddy/skills/mcpet/`，而仓库不在默认位置 → **询问用户仓库克隆路径**
3. 常见候选：当前工作目录、`~/mcpet`、`~/Documents/mcpet`

确认后统一用 `python "<项目根>/mcpet.py" <命令>` 调用（Windows 可用 `py` 替代 `python`）。

## 自然语言 → 命令映射

| 用户说 | 执行命令 | 说明 |
|--------|---------|------|
| 孵化 / 领养一只 / 开始养 | `python mcpet.py hatch --name <名字>` | 名字可询问用户，或先默认 |
| 同步我的麦当劳订单 | `python mcpet.py sync` → 确认后加 `--apply` | **先预览后确认**，见下方规范 |
| 模拟订单 / 随便玩玩 | `python mcpet.py simulate` → 确认后加 `--apply` | 无需 Token |
| 喂一个薯条 / 给它吃巨无霸 | `python mcpet.py feed "<食物名>"` | 从库存扣减，支持模糊匹配 |
| 我的精灵怎么样了 | `python mcpet.py status` | 转述阶段/经验/形态/库存 |
| 看看库存 / 还有什么食物 | `python mcpet.py pantry` | |
| 导出形象 / 看看它长什么样 | `python mcpet.py show --out mcpet.svg` | `--out xxx.png` 可导出形态图片 |
| 网页版 / 我想点着玩 | `python app.py` | 打开 http://127.0.0.1:8765 |

附加参数：`--state <文件路径>` 可指定独立存档（默认 `~/.mcpet/spirit.json`）。

## 输出规范（重要）

1. **同步必须两步走**：`sync` 默认是"干跑预览"（在克隆体上模拟，显示"将喂养 N 次、将变成什么形态"）。**必须先把预览结果转述给用户并得到确认**，再执行 `sync --apply`。这是防止手滑毁掉用户精灵的设计。
2. **status 转述要点**：精灵名、阶段（幼体/成形/完全体/变异体）、系别、经验进度、心情、库存总数。有进化/变异发生时着重提示。
3. **喂养失败**（库存里没有该食物）：提示用户先"同步订单"或"模拟订单"补充食物。
4. 命令输出是终端文本，用户看不到原始输出——**由你转述关键信息**。

## 典型工作流

**首次体验**：
1. `hatch --name 小薯`（孵化）
2. `simulate --apply`（模拟订单入库，立即有食物可喂）
3. `feed "薯条"` ×2 等（喂到 30 经验成形）
4. `status`（看结果）

**真实订单驱动**：
1. `sync`（预览：解析订单 → 套餐自动拆解 → 预计喂养次数与形态变化）
2. 用户确认 → `sync --apply`（食物入库，按订单号去重）
3. `feed "<食物>"` 逐个喂养；或 `status` 查看进度

## 注意事项

- 网页版与 CLI、Skill 三方共享同一状态文件，数据互通；不要并行跑多个实例写同一存档
- 不执行破坏性命令；用户要"重新开始"时，先备份 `~/.mcpet/spirit.json` 再处理
- 套餐（随心配/三件套）会被自动拆解为子项分别喂养，无需用户手动拆
- 素材版权：精灵形象素材为项目原创素材，仅在本项目内使用
